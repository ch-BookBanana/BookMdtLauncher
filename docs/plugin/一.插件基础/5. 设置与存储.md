# 一.插件基础 | 5.设置与存储

> 📌 设置分两套入口：
> - **插件自己的键**：`self.settings` 视图（v2 方式，`self.get_config/set_config`）
> - **宿主设置 / 通用值**：`register("core/settings")`（v3 的 BSettings）

## 设置存哪

`settings.json` 顶层分桶：宿主在 `"core"`，每个插件占一格（键 = 插件 id）：

```json
{"core": {"language": "zh-CN", "theme": 0}, "my_plugin": {"volume": 30}}
```

旧格式（平铺 + `pluginSettings`）读入时会自动迁移，下次存盘就是分桶形状。

## 插件自己的键：self.settings

```python
class MyPlugin(BMLPlugin):
    settings_defaults = {"volume": 50}

    def on_ready(self):
        self.log(self.get_config("volume"))   # 没存过 → 50
        self.set_config("volume", 30)          # 写值（会触发 watch_config）
        self.watch_config("volume", self._changed)

    def reset(self):
        del self.settings["volume"]            # 删存值 → 回落到默认值
```

- 视图只认自己那一格；**未声明的键写入会报错**（先 `declare` 或写进 `settings_defaults`）
- 跨桶读：`self.settings.other("core")`
- `self.set_config` 与直接写 `self.settings[k]`：前者会通知回调，后者不会

## 宿主设置：BSettings

```python
s = register("core/settings")       # BSettings
s.get("theme")                      # 读 core 桶
s.set("theme", 1)                   # 写
s.other("my_plugin")                # 读别的桶
```

## 私有文件

- `self.workspace` → `BML/pluginData/<id>/`（不存在自动建），放插件自己的数据
- `self.path("assets/x.png")` → 本插件目录下的文件（`${plugin}/` 只在加载期可定位）

## 设置组点：`core/setting`（`add` 底层逻辑被改过，与普通 Point.add 不同）

> ⚠️ **这条最容易误解**：设置组的 `add` 不是原版 `BPoint.add`，而是
> `BSettingPoint` **覆写过的 add**。内部先 `super().add(...)`（建条目、归属、
> 覆盖栈、通知照旧），再额外处理 `default=` 和 `build=`。
> 所以「设置条目 = 加一个控件」，不是「加一条元数据」。

分组是 `core/setting` 的子点，条目是子点上的设置项 —— 加一组、加一项都不用动设置页：

```python
from BMLCore import register, Widgets

group = register("core/setting")                       # BSettingPoint（不是普通 BPoint）
group.add("core.setting.mine", type="core/setting",    # 分组 = 子点
          title="my.group")
group.get("core.setting.mine").add(                    # 条目 = 设置项
    "probe", default=True, title="my.probe",
    build=lambda ctx: Widgets.control(ctx, Widgets.Bool))

register("core/setting").get("core.setting.mine").get("probe").get()   # True
```

| add 参数 | 做什么 |
|---|---|
| `名字` | 条目名（= 设置键） |
| `default=` | `super().add` 之后把初值 `set` 进去 |
| `build=` | 控件工厂：`build(ctx)` 返回控件（`ctx.parent/title/entry`） |
| `attr=` / `spacing=` | 挂到设置页对象上的属性名 / 这一项上方的空隙 |
| 其余 `**fields` | 照旧落成条目属性（`title`…） |

> 📌 元数据（标题、图标、说明）**不存条目**，`build(ctx)` 里手动传给控件。
>
> 📌 分组为空时设置页不摆那一组（插件那一组没装插件就是空的）。
>
> 📌 想再改行为，继承 `BSettingPoint` 覆写 `add`，内部照样 `super().add(...)`。

## 插件侧：Plugin.add_setting

设置页的最终形态是从 `core/setting` 建出来的，插件只需要声明：

```python
class MyPlugin(BMLPlugin):
    settings_defaults = {"greet": True}

    def __init__(self, host):
        super().__init__(host)
        self.add_setting("greet", Widgets.Bool, title="my.greet")   # 自动双向同步
```

`add_setting` 把控件接到插件自己的设置键上（值落在插件桶里），默认分组是
`core.setting.plugins`；也可以给 `build=` 自己画控件、自己接线。卸载时条目与控件
一起下台。

## 设置项控件接口：value / set_value / refresh

值型控件（`Widgets.Bool` / `Widgets.Combo` / `Widgets.Slider`）实现同一套方法，
所以“控件”和“存哪”互不认识 —— 接任何能读能写的对象都行：

| 方法 | 做什么 |
|---|---|
| `value()` | 界面上现在的值 |
| `set_value(v)` | 把值摆到界面上，**不发 push**（静音） |
| `refresh()` | 从数据源重新读一次，等于 `set_value(source.get())` |
| `push` | 信号，只在**用户真的动了界面**时发 |

`Widgets.bind(控件, 数据源)` 把两边接起来：灌初值、用户改动写回源、源变了界面自动刷新。

```python
from BMLCore import Widgets

# 1) 接 v3 设置条目（BValue：有 get/set/value_changed）
item = register("core/setting").get("probe")
sw = Widgets.bind(Widgets.Bool(ctx.parent, "设置测试开关"), item)

# 2) 接宿主设置（Settings 是映射，用 MappingSource 包一层）
sw = Widgets.bind(Widgets.Bool(ctx.parent, "深色主题"),
                  Widgets.MappingSource(events.settings, "theme"))
```

数据源只要满足：`get()` + `set(v)`，能通知变化更好（`watch(fn)` 或 `value_changed`
任选其一，`bind` 两种都认）。想自己画控件也行 —— 实现 `Widgets.SettingItem`
的三个方法加一个 `push` 信号，`bind` 照样接得上。

> ⚠️ `set_value()` 必须静音：它走的是“外部值摆上来”这条路，自己再发 `push`
> 会让“外部改动 → refresh → push → 回写”绕成环。`Bool` / `Combo` / `Slider`
> 内部都用 `blockSignals` 处理了，自绘控件记得照做。
>
> 📌 `Title` / `Line` 是装饰（分组标题、分隔线），不参与取值，没有这套接口。
