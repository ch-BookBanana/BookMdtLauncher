# 一.插件基础 | 3.注册语法

> 📌 **命令式用 `register`，装饰器用 `registrar`**。新插件一律用 v3 写法；
> `registrar(...)` 解析不到 v3 路径时会回退旧 v2 作用域（过渡期行为）。

## register()：拿自己的点

```python
from BMLCore import register

me = register()      # 当前 owner 自己的点（插件加载期 = 你的插件）
```

`register(path)` 按 key 找人：先自己点 → 再 core 点 → 再逐段往下：

```python
register("core/log")          # 宿主登记的 BLog
register("parts")             # 自己点下的子项
register("core/settings")     # 宿主设置（BSettings）
```

## add()：往点上加东西

| 参数 | 作用 |
|---|---|
| `顺序名` | 条目 key（同 key 反复 add 拿同一个实例） |
| `type=` | 要建的类型：`core/point`（子点）、`core/signal`（信号）、`core/value`（值）… |
| `entry=` | 子点的默认条目类型（子点以后 add 出来的东西按它建） |
| 其余 `**fields` | 直接成为条目属性（`title` / `icon` …） |

```python
parts = me.add("parts", type="core/point", entry="core/value")
parts.add("greeting").set("你好")

group = me.add("group", type="core/point", title="我的组", icon="x.png")
```

## 路径分隔：`$` / `&` / `#`

- 都是「往下走一层」的链分隔，不是目录分隔符
- `#` 归属自己；`&` 归属上一段的 owner（宿主点）
- 例：`register("core/settings&launcher&java")` 往宿主点上找/加

## registrar(path)：装饰器专用

```python
from BMLCore import registrar

@registrar("core/signals&on_game_start").connect()
def on_start(*args):
    ...

@registrar("settings$java$select_java.value_changed").connect()
def on_select(value=None):
    ...
```

- `.connect()` 不带回调 → 返回装饰器；带回调 → 直接订阅
- `.emit(...)` 直接发
- 其它能力透传：`registrar("core/log").info("…")`

## 加载会话

加载器在插件构造前开会话：构造期间 `add` 先暂存，构造成功才提交；
构造中途抛异常 → 整场登记回滚（见[生命周期](4.%20生命周期.md)）。

> 📌 构造里写的登记此时「别人还看不到」；不要在里面自己 `unload` 自己。

## 常见错误

| 报错 | 原因 |
|---|---|
| `KeyError: core xxx 下没有条目 'yyy'` | 路径拼错 / 宿主没登记 / 你还没 add |
| `不收 'xxx' 类型的条目` | 子点的 `entry=` 或 `point` 接受表不允许 |
| `缺必填字段` / `未知字段` | 登记进有契约的点时字段不对 |
| `注册点 'core/settings&launcher' 还没注册` | v2 路径语法下，宿主设置点没先 `contract()` |
