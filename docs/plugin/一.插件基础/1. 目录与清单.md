# 一.插件基础 | 1.目录与清单

> 📌 清单名只认 `data.hjson` / `data.json` / `data.toml`（按此优先级取第一个）。
> 旧名 `manifest.toml` / `plugin.json` 会直接报错，不会自动兼容。

## 目录布局

```
BML/plugins/my_plugin/
├── data.hjson          # 清单（必需）
├── main.py             # 入口模块（默认 main）
├── my_module.py        # 可选：插件自己的其它模块（from . import 可用）
├── langs/              # 可选：语言包（zh-CN.json …）
│   └── zh-CN.json
└── assets/             # 可选：资源（self.path("assets/x.png")）
```

也可以把整个插件打成 zip 丢进 `BML/plugins/`；zip 里多套一层目录也认。

## 清单字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 字母开头，只允许字母/数字/下划线；同时是包名与注册归属（owner） |
| `name` | | 显示名；不填就用 id |
| `version` | | semver（`1.2.0`）；依赖校验用 |
| `api` | | 兼容的宿主 API 范围，如 `"2.x"` / `">=2.0.0,<3.0.0"`；留空 = 不检查 |
| `entry` | | 入口：模块名（`main`）或「模块.类名」（`main.MyPlugin`），默认 `main` |
| `author` / `description` | | 展示用 |
| `dependencies` | | 数组；每项是「插件 id」或「约束表达式」，见下 |

```hjson
{
  id: my_plugin
  name: 我的插件
  version: 1.0.0
  api: 2.x
  entry: main.MyPlugin
  author: you
  description: 一句话说明
  dependencies: ["base_plugin", "other>=1.2.0,<2.0.0"]
}
```

## 入口规则

> 📌 `entry` 里不能有路径分隔符（`/`、`\`），也不能以 `.` 开头——那意味着
> 可能跑出插件目录去。

- `entry: main.MyPlugin` → 加载 `main.py` 里的 `MyPlugin`
- `entry: main` → 自动挑「定义在本文件里、且最派生」的 `Plugin` 子类
- 类名必须是合法标识符

## 依赖

- `"base_plugin"`：只要求装了这个插件
- `"base_plugin>=1.2.0,<2.0.0"`：对已安装版本求值
- `"1.2.0<=base_plugin<=1.5.0"`：双向夹

> ⚠️ 依赖没装或版本不满足 = **这个插件加载失败**；依赖链上的其它插件不受影响。
> 所以写依赖前先确认对方真的会装。

## 语言包

`langs/<语言>.json` 是语言键表；插件里 `register("core/lang").get("键")` 取。
宿主语言切换时插件语言包也会跟着换；卸载后回到内置文案。
