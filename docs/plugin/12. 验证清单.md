# 验证清单

## 一、冒烟脚本（自动化）

```powershell
python scripts/smoke.py                    # 全跑：装配 + 页面 + 设置项 + 信号 + 主题 + 语言
python scripts/smoke.py --verbose          # 打印每一步
python scripts/smoke.py --only=item,signals   # 只跑指定步骤
python scripts/smoke.py --keep             # 保留临时 BML 目录，便于翻日志
```

脚本会在临时 `BML/` 里现造两个插件（`example_lib` 与 `example_hello`，后者依赖前者），
然后走一遍「加载器 + BMLCore 门面 + 登记 → 宿主界面」整条链。它能覆盖的点：

| 覆盖点 | 检查内容 |
|--------|---------|
| 清单解析 | `data.json` 能被识别，`api = "2.x"`、`dependencies` 生效 |
| 依赖 | `example_hello` 依赖 `example_lib`，后者先加载 |
| 注册 DSL | `@registrar("core/pages").new(...)`、`registrar("core/setting/items")`、`registrar("core/tray/menu")` 落地 |
| 类属性标记 | `css = registrar("core/qss").new(...)` 的片段进了样式表 |
| 设置视图 | `settings_defaults` 声明 + 写值存活，不污染宿主键 |
| 语言包 | `langs/zh-CN.json` 生效，并会覆盖一个内置键 |
| 资源 | `${plugin}/assets/icon.png` 在构造期能取到绝对路径 |
| 信号 | `register("signals#名").new` + `connect` 能接到自己的 `emit` |
| 生命周期 | `on_ready` 被调用；卸载后条目、订阅、控件一起消失、内置文案回退 |

## 二、清单与目录

- [ ] 清单文件名只用其中一个：`data.hjson` / `data.json` / `data.toml`（有多个时按此优先级取第一个）
- [ ] 目录里**没有** `manifest.toml` / `plugin.json`（有就会被报「旧清单不再识别」）
- [ ] `id` 字母开头、只用字母数字下划线，且不是 `core` / `src` / `main` / `bmlcore` / `bmlplugin` / `bml_plugin`
- [ ] `version` 是 semver（如 `1.2.0`）—— 依赖约束按它比较
- [ ] `api` 与宿主兼容（`2.x` / `2.0.0` / 不写）
- [ ] `dependencies` 是字符串或字符串列表；约束表达式能解析（`"a>=1.2.0,<2.0.0"` / `"1.2.0<=a<=1.5.0"`）
- [ ] `entry` 指向插件目录里的裸文件名（缺省 `main.py`）
- [ ] `langs/<语言>.json`、`assets/`、`libs/` 都在插件目录里（若用到）

## 三、入口代码

- [ ] 插件类继承 `Plugin` 或 `BMLPlugin`，类属性 `id` 与清单一致
- [ ] 导入范围仅限 `from BMLCore import …` 与自己的相对导入（未 import `src.*` / `main`）
- [ ] 初始化写在 `__init__(self, host=None)` 中，首句为 `super().__init__(host)`
- [ ] `__init__` 中没有创建控件、没有阻塞（耗时活交给 `self.task` / `self.thread`）
- [ ] 登记一律是 `registrar("命名空间").动词(...)` / `self.register(...)`，没有 v1 的旧装饰器
- [ ] 装饰器方法返回**新控件**；托盘构建方法返回 `QAction`；设置项的 `section` 指向存在的分组 key
- [ ] 没有用到已移除的 API：`self.data` / `self.save_data()` / 自定义 `Signals` 类
- [ ] 所有写入的设置键都在 `settings_defaults` 里，或已 `self.settings.declare(...)`
- [ ] 卸载路径干净：`on_close()` 关文件 / 存数据；长任务轮询 `cancel_event`；不改全局状态

## 四、运行验证（手工）

```powershell
Get-Content BML\logs\latest.log -Tail 60 | Select-String "example_hello"
```

- [ ] 日志出现 `[example_hello]开始加载` 与 `[example_hello]加载完成`
- [ ] 界面出现登记的页面 / 设置项 / 托盘项，位置与 `order` 一致
- [ ] 切换语言后内置控件文案更新；卸载插件后，它覆盖过的内置键回到内置文案
- [ ] 切换主题后 `core/qss` 片段跟着走（浅色 / 深色各看一眼）
- [ ] 自己声明的信号能收到：`register("signals#名").emit(...)` → `connect` 的回调被叫到
- [ ] 令 `__init__` 抛异常后：只有该插件失败，启动器正常启动；下次启动日志里有「已标注停用」
- [ ] 修好后 `pluginLoader.enable("<id>")` 或触发一次重载，插件能起来
- [ ] 重载后：条目、订阅、控件、计时器、下载、线程都收干净（日志无重复回调、无悬空控件）
- [ ] 依赖版本不满足时，依赖方加载失败，依赖本身仍然加载成功
- [ ] `self.workspace` 里的文件在重载后仍然存在
