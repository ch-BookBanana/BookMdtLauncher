# 资源与依赖

## 插件资源

```python
from PySide6.QtGui import QIcon

from BMLCore import BMLPlugin, registrar


class Hello(BMLPlugin):
    id = "example_hello"

    def __init__(self, host):
        super().__init__(host)

        # self.path(相对插件目录) 返回绝对路径；任何阶段均可调用
        self.icon_path = self.path("assets/icon.png")
        self.icon = QIcon(self.icon_path)
        self.log("图标位于 %s" % self.icon_path)

        # 私有目录：不存在时自动创建，重装插件后仍然保留
        self.log("私有目录：%s" % self.workspace)

    @registrar.page(title="hello.page", order=50, icon="assets/icon.png")
    def build_page(self, ctx):
        return GreetPanel(ctx.parent)
```

写入私有目录：

```python
import os


def save_note(self, text):
    path = os.path.join(self.workspace, "note.txt")   # 目录不存在时自动创建
    with open(path, "w", encoding="utf-8") as f:
        f.write(text)
```

- 旧写法 `getPath("${plugin}/assets/icon.png")` 同样可用，但仅在 `__init__` 阶段有效；
  `self.path()` 不受此限制。
- 安装位置不作为依赖：更换目录或打包方式无需改动插件代码。

## 依赖

```toml
# BML/plugins/child/manifest.toml
id = "example_child"
version = "1.0.0"
api = "1.x"
dependencies = ["example_base"]     # 数组；只依赖一个时写字符串也认
```

```python
class Child(BMLPlugin):
    id = "example_child"

    def __init__(self, host):
        super().__init__(host)
        # 依赖先加载，此处已可读取 base 登记的条目
        from BMLCore import registry
        keys = [e.key for e in registry.entries("example_base.parts")]
        self.log("base 的零件：%s" % keys)
```

| 情况 | 表现 |
|------|------|
| 依赖先加载 | 依赖方的 `__init__` 中即可读取依赖方登记的条目 |
| 缺少依赖 | 该插件加载失败，日志中写明缺失的 id |
| 依赖成环 | 报出环，相关插件均不加载 |
| 依赖被停用或加载失败 | 依赖方随之失败 |

## 把代码提供给别的插件

两条路，按要共享的东西选：**纯代码直接 import，有状态的东西走注册表**。

### 一、注册表：交换「活对象」

提供方把自己的类、工厂、服务挂在一个对象上发布：

```python
# example_more：提供控件的一方
from BMLCore import Plugin


class FancyBool:
    """本插件自己的控件类，供别的插件构造。"""

    def __init__(self, label, color):
        self.label = label
        self.color = color


class Widgets:
    Bool = FancyBool                  # 类

    @staticmethod
    def divider(width=1):             # 工厂
        return "—" * width


class More(Plugin):
    id = "example_more"

    def __init__(self, host):
        super().__init__(host)
        # 发布到 example_more.widgets（落脚点是自动声明的 <id>.api 扩展点）
        self.publish("widgets", Widgets())
```

使用方声明依赖，然后取用：

```python
# example_user：manifest 里写 dependencies = ["example_more"]
from BMLCore import Plugin


class User(Plugin):
    id = "example_user"

    def __init__(self, host):
        super().__init__(host)
        self.api = self.use("example_more.widgets")   # 活句柄

    @registrar.page(title="user.page", order=60)
    def build_page(self, ctx):
        return self.api.Bool("标签", "red")               # 用对方的类
```

`self.use` 返回的是**活句柄**而不是对象本身：每次取属性才按 key 现查一遍。
于是把它存进 `self` 是安全的 —— 提供方重载之后，同一个句柄自然指向新那一份；
提供方被卸载时，用它就当场报错（并列出该扩展点现有的条目），不会拿到一个
已经失效的对象。

### 二、import：直接拿对方的代码

插件目录就是包，所以纯代码（控件类、工具函数、常量表）可以直接按包名 import：

```python
# A 的入口把要对外的东西转出来（当作门面）
from .panels import FancyPanel
```

```python
# B：manifest 里写 dependencies = ["example_more"]
from bmlplugin.example_more import FancyPanel          # A 的门面
from bmlplugin.example_more.panels import FancyPanel   # 也可直接拿它的子模块
```

名字是实名的（`bmlplugin.<id>`），不会与别的插件撞；A 卸载时这个包会从
`sys.modules` 里摘掉，重装 A 之后新导入拿到的是新代码。

代价是 **import 那一刻就冻住了**：模块级 import 拿到的是当时的类对象，A 之后被
重载，B 手里的旧引用仍指向旧代码。所以：

| 要共享的东西 | 用哪种 |
|---|---|
| 纯代码：控件类、工具函数、常量 | `from bmlplugin.<id> import …` |
| 有状态的服务、要跟着提供方生命周期走的东西 | `self.use("<id>.<名字>")`（活句柄） |
