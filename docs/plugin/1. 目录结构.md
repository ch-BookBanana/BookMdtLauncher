# 目录结构

## 安装位置

| 场景 | 位置 |
|------|------|
| 已安装的启动器 | exe 同级的 `BML/plugins/` |
| 本仓库内开发 | 仓库根目录的 `BML/plugins/`（不进版本库） |

```text
BML/plugins/
├── hello/                    # 一个插件对应一个目录
│   ├── manifest.toml         # 清单（必需）
│   ├── main.py               # 入口文件，由清单的 main 指定，缺省 main.py
│   ├── panels.py             # 自己的模块（相对导入：from . import panels）
│   ├── langs/                # 语言包，文件名即语言代码
│   │   ├── zh-CN.json
│   │   └── en-US.json
│   ├── assets/               # 插件资源，通过 self.path("assets/…") 获取
│   │   └── icon.png
│   └── libs/                 # 插件自带的纯 Python 依赖
│       └── tinytag/
└── other.zip                 # 亦可直接放入 zip 包
```

- `.zip` 会先解压到 `BML/.tmp/plugins/`，再按普通插件加载；包内多一层目录同样可识别。
- 插件私有数据存放于 `BML/pluginData/<id>/`（对应 `self.workspace`），重装插件后仍然保留。

## 多文件插件与自带依赖

插件目录本身是一个 Python 包：加载后就是 `bmlplugin.<id>`，目录里的 `.py` 是它的子模块
（`bmlplugin.example_hello.panels`）。自己的模块用**相对导入**取：

```python
# BML/plugins/hello/main.py
from tinytag import TinyTag                 # 自带依赖：位于 libs/tinytag/
from BMLCore import BMLPlugin, registrar

from . import panels                        # 同目录的 panels.py（相对导入）
from .panels import GreetPanel               # 或只把要用的名字拿进来


class Hello(BMLPlugin):
    id = "example_hello"

    @registrar.page(title="hello.page", order=50)
    def build_page(self, ctx):
        # ctx.parent 为宿主提供的挂载点，用作 Qt parent
        return GreetPanel(ctx.parent)
```

```python
# BML/plugins/hello/panels.py —— 与入口文件同级
from PySide6.QtWidgets import QLabel, QVBoxLayout, QWidget

from BMLCore import events


class GreetPanel(QWidget):
    def __init__(self, parent=None):
        super().__init__()
        lay = QVBoxLayout(self)
        lay.addWidget(QLabel(events.lang.get("hello.page.head")))
```

- 只有 `<插件目录>/libs` 会进 `sys.path`（那是自带的第三方依赖）；插件目录自己不进 ——
  靠相对导入就够，而且不会与别的插件「碰巧同名的模块」互相顶掉。
- 入口模块（`main.py`）就是包的门面：想让别的插件用某个类，在入口里
  `from .panels import GreetPanel` 转出来，对方就能 `from bmlplugin.example_hello import GreetPanel`。
