# 加载失败与停用

## 正常加载

```text
[example_hello]开始加载
[example_hello]加载完成
```

## 加载失败

```text
[example_hello]加载失败:
<Traceback ...>
[example_hello]已标注停用，下次启动不再加载它（修好后调 pluginLoader.enable(id)，或手动触发一次插件重载）
```

失败后的行为：

- **只影响该插件**：其它插件正常加载，启动器正常启动。
- **登记整体回滚**：本次写进注册表的条目全部退回，不会留半截条目（重试也不会撞「条目已存在」）。
- **报告一次**：「同一条失败只报一遍」—— 它既可能是别人的依赖、又轮到自己加载，
  不会刷两遍日志。
- **写进停用名单**：插件 id 追加到 `settings.json` 顶层的 `disabledPlugins`，并立刻落盘：

```json
{ "disabledPlugins": ["example_hello"] }
```

两类失败**不进**停用名单（它们是图上的问题或清单都没读出来，不该锁死用户）：

| 情况 | 原因 |
|------|------|
| 缺少依赖 / 依赖成环 / 依赖被停用 | 装上缺的那个、改掉环之后就该能起来 |
| 清单没读出来（占位 id 形如 `<目录名>`） | 写进去就是一条永远清不掉的垃圾 |

## 恢复方式

1. 依据日志里的 traceback 修好插件；
2. 把记录从停用名单里去掉 —— 任一做法都行：
   - 调用 `pluginLoader.enable("<id>")`；
   - 手动触发一次插件重载（重载会以 `retry_disabled=True` 重新尝试，再失败会重新标上）；
   - 直接编辑 `BML/settings.json` 的 `disabledPlugins`。
3. 重载或重启启动器。

> 当前版本没有界面入口执行上述操作，只能走接口或编辑 `settings.json`。

## 常见原因

| 现象 | 原因 |
|------|------|
| `插件不得 import 'src.utils.events'` | 导入了内部模块；插件只允许 `from BMLCore import …`（子模块用相对导入） |
| `缺少清单：data.hjson（或 data.json / data.toml）` | 插件目录里没有清单文件 |
| `旧清单 manifest.toml 不再识别：请改名为 data.hjson…` | v1 清单名不再支持 |
| `id 'x-y' 不合法：只能用字母、数字与下划线…` | id 里有短横线 / 点号，或首字符不是字母 |
| `要求 API 1.x，当前宿主是 2.0.0` | 清单的 `api` 与宿主不兼容 |
| `入口文件不存在：main.py` | `entry` 指向的文件不存在或没随插件提供 |
| `main.py 里找不到 entry_class = 'X'（要是 Plugin 子类）` | `entry_class` 名字有误，或该类不是 `Plugin` 子类 |
| `缺少依赖：example_base（没有这个插件…）` | 依赖没装，或它的清单没读出来 |
| `依赖版本不满足：example_base>=1.2.0（实际装的是 1.0.0）` | 依赖版本太低，升级依赖或放宽约束 |
| `依赖成环：a -> b -> a` | 两个插件互相依赖 |
| `插件 'example_hello' 没声明设置键 'voluem'` | 设置键没写进 `settings_defaults`，也没 `declare` 过（多半是拼错了） |
| 加载成功但界面无内容 | 登记了但构建方法没返回控件，或 `section` 指向了一个不存在的分组 |
