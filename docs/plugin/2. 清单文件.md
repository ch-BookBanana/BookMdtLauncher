# 清单文件

清单文件名按优先级**静默二选一**（实际是三选一）：`data.hjson` > `data.json` > `data.toml`。
同一个目录里只认一个 —— 写了多个时按优先级取第一个，不报错、不合并。

旧的 `manifest.toml` / `plugin.json` **不再识别**；目录里只有旧名而没有 `data.*` 时加载失败，
报「旧清单 `manifest.toml` 不再识别：请改名为 data.hjson（或 data.json / data.toml）」。

## 示例（data.hjson）

hjson 是 JSON 的宽松写法：支持 `//` 注释、无引号键、可省结尾逗号。

```hjson
// BML/plugins/hello/data.hjson
{
  id: example_hello             // 必需：字母开头，字母数字下划线
  name: Hello
  version: 1.0.0                // semver，如 1.2.0
  api: 2.x                      // 可选；空 = 不检查
  entry: main.py                // 可选，缺省 main.py
  entry_class: Hello            // 可选，缺省时自动发现
  author: you
  description: 示例插件
  dependencies: [example_base]  // 可选
}
```

等价的 `data.json` / `data.toml`：

```json
{ "id": "example_hello", "version": "1.0.0", "api": "2.x", "entry_class": "Hello" }
```

```toml
id = "example_hello"
version = "1.0.0"
api = "2.x"
entry_class = "Hello"
```

## 字段

| 字段 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `id` | 是 | — | 标识符；同时用作注册表命名空间、事件前缀、设置桶名与包名 |
| `name` | 否 | 同 `id` | 显示名 |
| `version` | 否 | `0.0.0` | 插件版本（semver）；依赖约束按它比较 |
| `entry` | 否 | `main.py` | 入口文件名，只能是插件目录里的裸文件名（不能带路径） |
| `entry_class` | 否 | 自动发现 | 入口类名；不写时取本文件中最派生的 `Plugin` 子类 |
| `author` / `description` | 否 | 空 | 说明性字段 |
| `api` | 否 | 空（不检查） | 兼容的宿主 API 范围 |
| `dependencies` | 否 | 空 | 依赖的插件；字符串或字符串列表 |

## id 的写法

`id` 只能用字母、数字与下划线，且**首字符是字母**。它同时是注册表命名空间、事件名前缀、
设置里的桶名，以及插件代码的包名（`bmlplugin.<id>`），所以**不接受点号与短横线**。

不能用保留名：`core`、`src`、`main`、`bmlcore`、`bmlplugin`、`bml_plugin`。

建议把作者名融进 id，避免与别人的插件重名：

```hjson
id: bookbanana_more_widgets     // 作者_插件
id: ncatbot_plugin_market       // 也可再加一层用途
```

同一个 id 不允许装两次：发现重复时两个插件都会被标为加载失败，日志里写明是哪两份。
`id` 定了就别改：注册表条目 key、事件名、设置桶、`pluginData/<id>/` 都按它算。

## api 版本号

宿主当前 `API_VERSION = "2.0.0"`：

| 写法 | 含义 | 宿主 2.0.0 是否接受 |
|------|------|---------------------|
| `2.x` | 同一大版本（推荐） | 是 |
| `2.0.0` / `2.0` / `2` | 精确版本（只比到大/次版本） | 是 |
| `>=1.0,<2.0` | 区间 | 否（宿主 2.0.0 已超出上界） |
| `1.x` | 要求 v1 宿主 | 否 |
| 不写 | 不检查兼容范围，直接尝试加载 | — |

## dependencies：字符串或字符串列表

只依赖一个时写字符串，多个时写列表；**每一项可以带约束表达式**：

| 写法 | 含义 |
|------|------|
| `"example_base"` | 只要装着就行（不限制版本） |
| `"example_base>=1.2.0,<2.0.0"` | 单边多条件：>=1.2.0 且 <2.0.0 |
| `"1.2.0<=example_base<=1.5.0"` | 两边夹：名字写中间 |
| `"example_base==1.4.0"` | 精确版本 |

```hjson
{
  id: example_child
  version: 1.0.0
  dependencies: [example_base>=1.2.0,<2.0.0]   // 也支持 "1.2.0<=example_base<=1.5.0" 这种写法
}
```

- 版本比较只取前三位（`1.2` 补成 `1.2.0`）。
- 校验对象是**依赖已加载后的实际版本**（清单里的 `version`）；不满足 = 这个插件整体加载失败，
  依赖链上的其它插件不受影响。
- 依赖被停用 / 加载失败 / 成环时，依赖方也起不来（见[加载失败与停用](<10. 加载失败与停用.md>)）。

## 报错信息

| 情况 | 日志内容 |
|------|---------|
| 没有 `data.*` 也没有旧名 | `缺少清单：data.hjson（或 data.json / data.toml）` |
| 只有旧名 | `旧清单 manifest.toml 不再识别：请改名为 data.hjson（或 data.json / data.toml）` |
| 解析失败 | `data.hjson 读不了或不是合法清单：…` |
| 顶层不是对象 | `data.hjson 顶层必须是一个对象` |
| `id` 缺失 / 非法 / 保留名 | `data.hjson 缺少 id` / `id '…' 不合法：只能用字母、数字与下划线…` / `id '…' 是保留名（…）` |
| `entry` 带路径 | `入口文件名 '…' 不合法：只能是插件目录里的文件名` |
| `dependencies` 类型不对 | `dependencies 必须是数组` / `dependencies 里只能是字符串，收到 […]` |
| 依赖了自己 | `依赖了自己：example_child` |
| 与别的插件撞 id | `id 与另一个插件重复：example_hello（a 与 b）` |
| 找不到入口类 | `main.py 里找不到 entry_class = 'X'（要是 Plugin 子类）` |
