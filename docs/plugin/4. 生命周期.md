# 生命周期

```text
扫描 BML/plugins
 └─ 读清单（data.hjson > data.json > data.toml；清单不合法时立即报错）
     └─ 按 dependencies 先加载依赖（缺依赖 / 成环 / 版本不满足 → 本次加载失败）
         └─ 导入入口文件 → 选定插件类（entry_class 或最派生子类）
             └─ cls(host)                构造：初始化与登记（写在这里或装饰器上）
                 └─ registrar.apply(...) 装饰器与类属性上的标记在这里落地
                     └─ 全部插件加载完成 → 每个实例 on_ready()（界面还没建）
                         └─ 界面按注册表构建

卸载（重载 / 停用 / 退出）：
 └─ 摘注册条目与事件 → on_close() → 宿主调 cleanup() → 删它造的控件
```

## 示例

```python
from BMLCore import BMLPlugin, Widgets, registrar


class Hello(BMLPlugin):
    id = "example_hello"
    settings_defaults = {"greet": True}

    def __init__(self, host=None):
        super().__init__(host)                 # 首句：保存 host
        self.cache = {}                        # 插件自身的初始化
        self.log("开始加载")
        self.register("signals#hello").connect(self._on_hello)   # 订阅记在自己名下

    def on_ready(self):
        # 所有插件都加载完、界面还没建：适合做跨插件初始化
        self.log("就绪")

    hello = registrar("signals#hello").new()  # 类属性标记，apply 时落地

    @registrar("core/setting/items").new(title="hello.greet", section="core/setting/plugins")
    def build_greet(self, ctx):
        return Widgets.Bool(ctx.parent, ctx.title)

    def _on_hello(self, what):
        self.log("自己的信号到了：%s" % (what,))

    def on_close(self):
        self.log("清理完成")                    # 停线程、关文件、把要留的写进设置
```

## 约定

- **登记是全有或全无**：构造里抛异常 = 这个插件没加载起来，注册表的加载会话整体回滚，
  不会留下半截条目，重试也不会撞「条目已存在」。
- **失败互相隔离**：单个插件失败不影响其它插件，也不影响启动器启动。
- `on_ready()` 里 `sys.exit()` 也会被接住（记日志），不会拖垮别的插件或宿主；
  同理 `on_close()` 抛异常也只记日志。
- **构造里不要建控件、不要阻塞**：界面还没构建。耗时操作放 `self.task(...)` / `self.thread(...)`
  或 `on_ready()`。
- **卸载顺序**（由宿主执行，顺序有讲究）：先摘注册条目与事件（界面可能还在，条目先消失总比
  指向已销毁对象好）→ 再调 `on_close()`（关文件、存数据；失败回滚时也会调，所以要容忍残缺状态）
  → 之后宿主调 `cleanup()` 收计时器 / 下载 / 线程 → 最后删它造的控件。
- **重载**（手动触发）会整批卸载再重建；插件的设置与 `workspace` 保留。
