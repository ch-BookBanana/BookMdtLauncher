# 二.主程序扩展点 | 6.内置信号

宿主信号登记在 `core/signals` 点（`core/signal` 类型条目）。订阅方式：

```python
@registrar("core/signals&on_game_start").connect()
def on_start(*a): ...
```

| 信号名 | 参数 | 说明 |
|---|---|---|
| `plugins_changed` | — | 插件集合变化（加载/卸载/重载后） |
| `reload_plugins` | — | 请求重载插件层 |
| `tokenVerified` | ok, user, err | GitHub token 校验结果 |
| `overlayRequested` | widget | 请求打开叠加层 |
| `overlayClosed` | widget, closed | 叠加层关闭 |
| `stackRequested` | widget | 请求打开浮层栈页 |
| `stackClosed` | widget, closed | 浮层栈关闭 |
| `java_status` | status, pct | Java 下载进度状态 |
| `closeRequested` | choice | 关闭窗口的选择（tray/quit） |
| `start_gameChanged` | game | 当前游戏变化 |
| `core_tick` | 值 | 内部节拍（测试用） |

> 📌 v3 下这些名字会被宿主桥接进 `core/signals` 点（`core/eventsignal` 类型，
> 内部转发到 events 总线）。插件统一这样订阅，不直接碰 events：

> ```python
> @registrar("core/signals&on_game_start").connect()
> def on_start(*a): ...
> ```

> 以宿主 `main.py` 里 `self.signals.register(...)` 的实际登记为准；v3 迁移后
> 这些名字会同步进 `core/signals` 点，插件仍用 `register("core/signals&名字")`。
